# M0 — AI Spike

## Hypothesis

A small, precision-first pipeline can transform evidence legitimately exposed by a social URL into place candidates and verified geographic entities without downloading the video or asking the user for an upload.

## Scope decision

M0 accepts URLs only. TikTok is the first provider under validation, Instagram is next, and YouTube is deferred. A source that cannot expose enough legitimate URL evidence returns `insufficient_evidence`; upload is not a fallback.

## Spike sequence

### M0.1 — Contracts and failure modes

- Typed source, evidence, candidate, resolved-place and analysis contracts.
- Social adapters explicitly model unavailable or insufficient evidence.
- LLM output remains candidate evidence; only a `PlaceProvider` verifies geographic truth.

### M0.2 — TikTok URL evidence acquisition

Input: `https://vt.tiktok.com/ZSq4UprxR/`

- validate the submitted HTTPS TikTok URL
- send the original URL to TikTok's official oEmbed endpoint
- validate the response with Zod
- obtain the canonical post URL and content ID from provider-owned embed metadata
- expose description, author and thumbnail references as `Evidence[]`
- do not follow the user-controlled short URL or download media

The deterministic unit suite uses provider fixtures. The opt-in live contract test must run in the same runtime and egress environment as the deployed service:

```bash
npm run test:integration:tiktok
```

Expected live evidence includes the candidate name `Madre` and the location hint `Pinheiros`. These values are not yet a verified place.

#### Deployment validation

`railway.toml` configures a Railpack build, `npm start`, and `GET /health`. The accompanying HTTP process is a narrow, authenticated probe shell around the CLI pipeline, not product API infrastructure.

Set `PROBE_TOKEN` as a Railway service variable, deploy the draft PR, then run this command from a trusted terminal against the generated domain:

```bash
SAVEPLACE_PROBE_URL="https://your-service.up.railway.app" \
PROBE_TOKEN="your-secret" \
npm run test:railway:smoke
```

The probe evaluates only `ZSq4UprxR`, does not accept arbitrary URLs, and emits canonical identity plus evidence types/counts — never raw caption or other provider payload. A passing response proves deploy -> egress -> TikTok oEmbed acquisition in that runtime. It does not prove M0.3 extraction or M0.4 place verification.

If `PROBE_TOKEN` is missing or scoped to the wrong Railway environment, the process now still starts and `/health` returns `200`; the protected probe returns `503 {"error":"probe_unavailable"}` without running acquisition. This preserves a useful deployment diagnostic while failing closed. Configure the exact `PROBE_TOKEN` service variable and redeploy before treating a smoke result as M0.2 evidence.

### M0.3 — Structured extraction

`OpenAIPlaceExtractor` calls the Responses API with strict JSON Schema output and Zod validates the returned structure. It submits only title, description, page metadata and transcript evidence when an adapter legitimately exposes them; TikTok M0.2 currently contributes only its oEmbed description. A candidate must identify the acquired evidence indices that support it; the adapter removes names and hints not literally present in that selected evidence.

The default model is `gpt-5.6-luna`, with a maximum of five candidates per source, 700 output tokens, 8,000 eligible evidence characters and a 10-second timeout. Every result carries provider, model, prompt version, duration, input/output tokens and estimated USD cost. Without `OPENAI_API_KEY`, it returns `unavailable` with no outbound request; provider/network/schema failures return `failed` with no candidates.

Use `OPENAI_API_KEY` only in an untracked local environment or Railway service variable. The default test suite uses deterministic provider fixtures and does not contact OpenAI.

### M0.4 — Place resolution

`GooglePlacesProvider` is the first real `PlaceProvider`. It calls Places API (New) Text Search with a minimum field mask: ID, display name, formatted address, coordinates and address components. It only returns a verified match when the provider returns a name, city, country and coordinates; ambiguous or malformed responses remain `needs_review`.

The default M0 guard permits at most **500 Text Search calls per UTC month per process**, well below the current Google free allowance. It fails closed once that budget is exhausted. It is intentionally not a global billing control: M1 replaces it with a transactional usage ledger shared across workers and Railway replicas. Set provider-side quotas and budget alerts as a second line of defense.

The adapter is opt-in and is not wired into the Railway TikTok probe. Run its live contract only with a restricted Google API key in a trusted shell:

```bash
GOOGLE_MAPS_API_KEY="your-restricted-key" \
npm run test:integration:google-places
```

M0 does not persist Google response content. This is important for compliance with Google Places caching restrictions; M1 may retain the provider place ID and must re-check the provider terms before storing/displaying any provider response fields.

### M0.5 — Evals

Grow from the first case to 10–15 real URLs, then 50. Measure extraction precision/recall, resolution accuracy, category accuracy, manual correction rate, latency and cost per successfully resolved place.

## First acceptance case

```text
vt.tiktok.com/ZSq4UprxR
  -> TikTok official oEmbed
  -> canonical TikTok URL + content ID
  -> caption/author/thumbnail Evidence[]
  -> PlaceCandidate[]
  -> PlaceProvider
  -> VerifiedPlace[]
```

M0.2 is complete when the short URL reliably produces real provider evidence in the target runtime. M0 as a whole remains incomplete until extraction and place resolution identify and verify the establishment without inventing an address.
